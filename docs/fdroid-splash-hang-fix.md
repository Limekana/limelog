# F-Droid splash-screen hang — investigation & fix

**Branch:** `claude/fdroid-splash-screen-hang-0iorb9`
**Reported (F-Droid MR review):** *App gets stuck on the gradient splash screen, no content gets rendered.*

## Summary

On F-Droid (and any device that cannot reach Google) the app hung on the
native gradient splash (`res/.../splash.png`) and never rendered the React UI.
The cause was a **render-blocking external Google Fonts stylesheet** in
`index.html`. The fix self-hosts the fonts so first paint no longer depends on
the network, and removes the third-party Google request (which F-Droid
disallows anyway).

## Root cause

`index.html` pulled the Barlow / Barlow Condensed fonts from Google:

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link href="https://fonts.googleapis.com/css2?family=Barlow+Condensed:wght@400;500;600;700&family=Barlow:wght@400;500&display=swap" rel="stylesheet" />
```

A `<link rel="stylesheet">` in `<head>` is **render-blocking**: the WebView
delays its first paint until that stylesheet either loads **or fails**. When
`fonts.googleapis.com` is unreachable — F-Droid users who firewall Google, or a
device that is simply offline — the request stalls instead of failing fast, so:

1. The Activity shows the native launch theme's window background
   (`@drawable/splash`, the gradient) during cold start.
2. The WebView loads `index.html` but blocks first paint on the Google Fonts
   request.
3. The gradient splash is therefore never covered → **"stuck on splash, no
   content."**

It worked in normal dev/desktop testing only because those environments
*reset* the connection almost instantly, which unblocks paint. Reproduced by
loading the built app with every non-localhost request aborted (see below).

## Why it wasn't the JS / auth logic

Ruled out before landing on fonts:

- **App splash gate (`App.tsx` `isResolving`)** — resolves fine. `isGuestMode()`
  is synchronous; `nexusStore.init()` wraps its network calls in try/catch and
  returns early when `isNexusConfigured` is false.
- **`nexusStore.init()` pre-try calls** (`initOAuthDeepLinkListener`,
  `outboxInstallTriggers`) — only add event listeners / register a deep-link
  handler; they don't throw.
- **Native SSO (`SuiteSsoPlugin.getNexusSession`)** — never rejects; every
  failure path (NCC not installed, no session, cert mismatch) calls
  `call.resolve({ available:false, ... })`.
- **`import.meta.env` / clean-build env vars** — already fixed in v1.8.1;
  Supabase URL/key have hardcoded defaults, and no other env usage exists.
- **Release minification** — `minifyEnabled false`, so not an R8/ProGuard issue.
- **Desktop browser render** — the built app renders the first-launch screen
  correctly; the only external request was the (fast-failing) Google Fonts one.

## The fix

Self-host the fonts (F-Droid-correct: no external calls, works offline).

- Downloaded the **latin-subset woff2** for Barlow (400, 500) and Barlow
  Condensed (400, 500, 600, 700) into `public/fonts/` (~130 KB total). Latin
  covers en/de/es (accents, umlauts, ñ, ß live in Latin-1); CJK falls back to
  system fonts exactly as before, since Barlow ships no CJK glyphs.
- Removed the two `preconnect` links and the Google stylesheet from
  `index.html`.
- Added `@font-face` declarations in `src/index.css` pointing at
  `/fonts/*.woff2`, each with `font-display: swap` (text stays visible in the
  sans-serif fallback while the woff2 loads).

### Files changed

| File | Change |
|------|--------|
| `index.html` | Removed Google Fonts `preconnect` + stylesheet `<link>`s; added explanatory comment |
| `src/index.css` | Added six `@font-face` rules for the self-hosted woff2 |
| `public/fonts/*.woff2` | Added six self-hosted font files |

> Note: `android/app/src/main/assets/public` is gitignored and regenerated by
> `npm run cap:sync`, so no native asset needed committing — the next sync
> copies `dist/` (fonts included) into the APK automatically.

## Verification

- `npm run build` — succeeds; fonts bundle into `dist/fonts/`.
- `npm run lint` — clean.
- **Offline repro/verify:** served `dist/` and aborted every non-localhost
  request (simulating the firewalled/offline device). The old build stalled on
  first paint; the new build renders the full first-launch screen with **zero
  external requests** and the local Barlow font applied.

## Follow-up (not addressed here)

The launch theme `AppTheme.NoActionBarLaunch` uses `parent="Theme.SplashScreen"`,
which is non-standard for the Capacitor Android template. It did not cause this
hang (the WebView covers the splash once it paints) and was left unchanged, but
it's the place to look if the splash ever lingers briefly after content is ready.
